# First real-chain test (GitHub Actions, 2026-10-11)

Run: workflow `live-chain-test` on commit 7b2d704. Raw reports: branch `live-test-reports` (probe.md/json, live_verify.md/json).

## Ethereum mainnet: PASS
* 150 consecutive blocks (26,166,966 - 26,167,115), 12-block confirmation depth, ingested through **drpc** (public endpoint, 10 blocks per query).
* 74,579 logs stored with tx hash / block number / block hash / log index. Independent re-read through **publicnode**: block hashes identical, log set identical (0 only-stored, 0 only-independent).
* Decoded 73,181 (ERC-20 Transfer 70,465; Uniswap V3 Swap 1,818; Uniswap V2 Swap 898); 0 decode errors; the remaining 1,398 are logs deliberately not decoded (ERC-721 Transfers share the ERC-20 signature, 4 topics).
* Resume from the cursor (20 more blocks, 6,199 logs): no duplicates, 0 reorgs observed, 0 non-canonical blocks.
* Cost: 73 s for 150 blocks on a free endpoint (about 500 logs per block on Ethereum).

## Base: NOT VERIFIED
Only one usable provider (publicnode, 1 block per query). base-official and drpc returned HTTP 429 (public rate limit); ankr needs an API key; llamarpc/1rpc answered 52x. A second independent provider is required for the cross-check.

## What the probe showed about public endpoints
* The default Python User-Agent is rejected with 403 by many gateways (fixed: identifying User-Agent).
* publicnode: topic-only `eth_getLogs` allowed for 1 block per query ("specify an address" above that). drpc: 10 blocks, max 20,000 results per query.
* llamarpc, 1rpc, cloudflare: unusable from GitHub runners (52x / "Cannot fulfill request"). ankr: needs a key.
* Consequence: scanning ALL Transfer/Swap logs of a busy chain is heavy for public endpoints. A paid/free-tier keyed provider, or an address watch-list (specific pools/tokens), is the realistic next step.

## Not covered by this test
No reorg occurred during the run, so reorg handling is still proven only on the fake chain. Wallet attribution and USD pricing are not implemented.
